# vNext 使用体验优化

实施依据：`NickYoung_UX_Optimization_Plan_Package.zip` 中的 vNext 1.0 方案。代码基线为 `b517b30bdd3428595dffef6156bcec73f6419048`，基线工作区无未提交变更，原有 29 项测试通过。基线截图保存在 `evidence/ux-vnext/baseline-*.png`。

## 已实现

| 工作包 | 修改与用户体验 |
| --- | --- |
| S0 | 保留基线测试与截图；增加可重跑的 Playwright 隔离服务和事件夹具 |
| S1-01 | 新建空项目、最近项目、手动目录三种入口；创建阶段反馈、防重复提交；失败保留需求和附件 |
| S1-02～04 | 首屏展示当前动作、负责人、通过数量、待决定数量、最近交接和下一步；最近 8 条关键进展，原始日志按需分页；按会话保存草稿、选中项与阅读位置；保留展开状态、避免重复高亮；版本更新由用户触发 |
| S2-01～03 | 抽离真实事件投影；1～8 人自适应布局；超过 8 人聚合；派发、送审、返修、问答保留原始 eventId；新事件单次动画，首次进入、重连、暂停与减少动态效果不重播；选中成员与交接保持 |
| S2-04 | 手机团队抽屉提供遮罩、关闭、Esc、焦点循环与返回；桌面增加专注阅读入口 |
| S3-01 | 决策使用具体选项文案，背景缺失时明确提示；提交防重复、失败可重试、答复后确认 |
| S3-02 | 成果摘要、机器验收通过与失败次数、独立审查、提交、未通过任务、使用方式；文件 diff、原始证据、完整报告与继续修改入口 |
| S3-03 | 保存影响范围说明；高级参数折叠；连接测试与目录发现分开；测试结果带时间并在扫描后保留，扫描不覆盖当前模型 |
| S4 | 黑白灰冷蓝，无绿色；增强状态文字、焦点与减少动效；长日志限制默认渲染量；深浅色与六视口回归 |

`public/studio/event-projection.mjs` 集中管理状态和摘要；`draft-manager.mjs` 管理本地草稿；`agent-graph.mjs` 管理连线和布局。`app.js` 继续接入已有 API，保留现有 DOM 和样式入口。服务端仅更新静态资源白名单和 UI 版本号，没有数据库迁移或调度流程改造。

## 验证边界

自动化性能包含本机负载差异；`browser.json` 同时记录包含 200ms 防抖的总耗时和响应到 DOM 观测的上界，不等同于网络延迟或精确 CPU 耗时。5000 条历史仍可输入、日志默认分页，不能据此声称任意数据规模都满足 250ms。

尚未进行 3～5 位新用户的 3 秒理解测试、真实手机软键盘与读屏器人工试用。工程回归与真实开发闭环已经覆盖；这些人工可用性指标保留为后续产品验证，不报告为已通过。
