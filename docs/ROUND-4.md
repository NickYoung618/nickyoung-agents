# 成果工作台持续交付

## 分阶段验收

| 阶段 | 实施边界 | 验收 |
|---|---|---|
| 1 可靠交付 | 排空、限时退出、就绪租期、类型化交付门槛 | 活跃浏览器/空闲 TLS 可退出；问答无成果可回答；缺失/失败成果不能收工 |
| 2 可见可用 | 六会话历史整理、项目归一、版本导航、搜索归档、完整包、静态/锁文件 Node 构建 | 历史逐项记录；干净目录解包可使用；历史网页可操作 |
| 3 持续迭代 | 版本输入范围、代码/使用/验收数据分离、兼容升级与迁移、需求和插话追踪 | 无关提交不增版本；失败升级保留旧版；反馈与数据留存 |
| 4 性能与发布 | 索引/投影、分页/大对象分离、资源队列、上下文、版本化发布及恢复演练 | 长历史增量有界；资源不足排队；版本一致；备份副本可恢复成果 |

验证分为单元/状态机、隔离服务和进程、浏览器、真实模型任务四类。生产只做只读检查和经隔离验证的历史成果登记，不在生产成果中注入测试数据。

## 数据与发布约定

- 新事件表增加 `(conversation,id)` 与 `(conversation,type,id)` 索引，投影持久保存游标。摘要读取投影，仅补投影之后的事件；原日志分页读取，大检查点和大输出保存在独立 payload 表，回滚旧服务前可还原原事件形状。
- 成果输入使用 Git 已有 blob 标识跟踪相对模块、HTML/样式/静态资源、锁文件及显式 inputs；不因 README 等无关提交增版。构建缓存摘要用于避免重复 npm 安装和构建，发布摘要用于避免传输全量源码核对资源一致性。
- 使用数据独立保存在 `data/usage/`，不同版本不隐式共享。新版独立验收后，明确点击升级：停止旧预览、备份数据、迁移候选副本、对副本运行场景，通过后启用新版。失败恢复旧预览，保留原数据及备份。验收副本不写回使用数据。
- 默认总预算 4：模型/安装构建/浏览器验收各占 2，持久预览占 1；不足时排队并记录原因。预览最多 2，验收最多 2。Node 预览堆 128MB，准备进程堆 384MB，安装/构建分别限时 120 秒，验收限时 60 秒。首版只支持静态站点和锁文件 Node；原生扩展、Docker、Python、WebSocket 和外部服务认证不伪装为可用。
- 临时验收与示例完成即清理，启动清理中断验收目录；空闲窗口可清理 30 天未活动缓存。成果、使用数据、升级备份及发布版本不自动删除。
- 源码包按固定提交与安全文件范围导出，排除凭据、数据、node_modules、缓存；包含独立使用说明。构建产物包包含静态成品与说明。
- 发布复制实际源码到不可变 `data/releases/<version>-<revision>/`，依赖按锁文件单独保存，systemd drop-in 指向发布目录和原数据路径，避免原工作区编辑混用资源。新进程先以维护状态启动，核验后激活。回滚默认保留当前数据库与使用数据。

首次从没有维护 API 的 artifacts-3 接管时，在无任务窗口验证目标 PID 后，只通过 loopback Node inspector 临时安装写入排空与连接关闭钩子；不跳过停止状态保存，不以 SIGKILL 代替正常退出。后续发布全部使用认证维护 API。检查失败会撤销临时维护；激活失败自动恢复先前代码。该接管仅用于一次版本兼容，不改变模型配置和登录。

场景操作符 `text` 明确表示“匹配集合中至少一个节点包含预期文本”，避免已有用户条目使 `#list li` 只检查第一项而误失败。验收记录包含该契约版本；原失败及原用户数据均保留。

使用目录通过 `NY_DATA_DIR` 提供给新 Node 应用，协议的 directories 同时兼容相对数据子目录。声明使用数据的服务只允许写入其使用数据目录，代码快照只读；旧协议没有声明数据目录时继续按版本隔离，不自动宣称兼容。源码归档随固定提交保存在 data/source-archives，备份恢复后不依赖原仓库才能打开准备好的成果或下载源码。外部原项目目录及未提交用户文件仍需按项目目录备份，不把服务备份说成所有外部工作区的完整备份。

## 发布与恢复操作

```bash
# 工作区准备完成后，检查测试和明确的发布分支再执行
node scripts/release-round4.mjs
# 仅代码回滚，默认保留当前数据库与用户数据
node scripts/rollback-round4.mjs /绝对路径/data/backups/round4-时间
```

发布记录 `evidence/round4-20261113/deployment.json` 保存发布目录、提交与备份位置。备份的 `actual-running-code.tar` 是切换前实际目录；首次从可变工作区切换时另有 `known-good-code.tar` 保留开始工作前的 artifacts-3 源码，绝非 HEAD 归档。SQLite 使用在线一致性备份；维护排空停止预览后复制 usage，避免数据写入与文件备份交错。

灾难恢复先在新目录解包实际代码、`events.sqlite`、artifacts、source-archives、usage 与必要配置，设置 `NY_DATA` 为新目录；证书/key 和原登录材料保留其权限。启动时旧 usage 绝对路径和软链接按新数据根重定位。先用不同的 `NY_PORT`、`NY_HOST=127.0.0.1` 验证会话/成果和数据，再调整正式服务；禁止直接把旧数据库备份覆盖当前生产数据库。可重复演练脚本为 `scripts/round4-restore.mjs`。

回滚到 artifacts-3 会保留新数据表，并在启动前把独立 payload 还原到旧事件形状；新版静态构建成果等新能力应重新切回 workbench-4 使用。代码回滚不还原数据库或外部服务。

## 支持边界

支持静态网页、锁文件 Node 项目、文档、CLI/库调用示例及已有项目回归；原生扩展需要安装脚本、Python/Docker、WebSocket 和外部服务认证不在预览支持范围。未声明 data 协议的历史 Node 应用维持版本内数据，不推断跨版本兼容。迁移必须显式声明且在数据副本验证，通过后才启用；不提供通用数据库迁移器和三方代码合并器。

手机验收为 Playwright 多视口、焦点、草稿、抽屉和溢出检查；真实手机软键盘、读屏器及用户人工验收仍待实际用户操作。恢复演练覆盖服务保存的成果与使用数据，外部项目目录的未提交改动仍需单独备份。

未变化且提交相同的成果由新任务明确登记复用关联，重复收集同一任务不会重复登记；备用项目命令路径保留真实退出码与输出、清理运行槽并单独计时。最终发布为 `20261114-workbench-4.2`，项目页推荐版本可直接进入使用及修改入口。
